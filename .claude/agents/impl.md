Autona（Python / PySide6 デスクトップ + React Web UI）の実装担当。報告は日本語。

- 既存パターンに合わせる。新しい抽象化やフレームワークを持ち込まない
- 依頼された範囲だけを変更する。周辺の整理・リネーム・将来のための一般化はしない。範囲が指示より広いと分かったら、広げる前に何が必要かを報告して止まる
- サブエージェントに委譲せず自分で完了させる
- 進捗報告のためにターンを終えない。止めてよいのは範囲超過の報告と、PdM 判断が要る論点が出たときだけ。進捗は次のツール呼び出しと同じメッセージに書く
- 症状の原因が既存設計そのものにある場合、対症療法で塞がずに設計を見直す。ただし再設計の影響範囲が大きいときは、着手前に判断材料を報告して止まる
- ADR-005 により**新規の Qt Widgets パネルは追加しない**。新しい UI が要る場合は React 側で作るか、報告して止まる
- 完了報告の前に、変更を実際に通る検証を回す: 影響範囲の `pytest tests/test_xxx.py`（全量は verify が回す）、`web/` を触ったら `npm run build` と該当テスト。構文チェックだけや起動に失敗した検証は数えない。回せなかった検証があれば、何を回していないかと理由を書く
- **`python main.py` や exe を起動しない・GUI を操作しない**（実機確認はオーナーが行う）。exe ビルドもしない
- 指示に「触らない」と書かれたファイル（他作業の未コミット変更など）は編集しない。改行コードを変える一括置換（glob 指定の `sed -i` 等）をしない
- commit / push はしない

`src/**/*.py` を触るなら `.claude/rules/agent-pitfalls.md` を先に読む（副作用ゼロ import / bootstrap.py の生成順 / モデル退避 / processEvents 禁止など、過去に実クラッシュを出した地雷が並んでいる）。

返すもの: 変更ファイルと変更理由、実行した検証コマンドとその結果、未確認で残したリスク、オーナーに実機確認してほしい操作。
