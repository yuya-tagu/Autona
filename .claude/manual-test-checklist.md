- [ ] 表示 ON が 4 名に達すると残りのチェックボックスが無効化される

## 配信設定（Stream Settings）

Web 版だけ（サイドバー Setup の「配信設定」= 共有ビューの `/web/stream`。ADR-005 S4e）。処理は core の `StreamService`（S4d）。Qt 版は S4e で削除済み。実況・解説と同じ共有ビューに出る。

- [ ] サイドバーで「配信設定」と「実況・解説」を交互に開くと、それぞれのページが出る（どちらから先に開いても、再起動後に最後に開いていた方から始めても）。ページの切り替えでビューは再読み込みされず、入力中の内容が残る
- [ ] 配信設定を一度も開かずに大会を読み込む → 配信設定を開くと、タイトルが「大会名 ft. 上位の参加者 ... and more! - 略称」で入っている（参加者の取得が終わる前は「大会名 - 略称」）。欄の下に「自動生成されたタイトルです」と出る
- [ ] タイトルを手で書き換える → 欄の下が「手入力したタイトルです」になる。別の大会を読み込んでも手入力のまま。**再起動しても手入力のまま**。欄を空にしてから大会を読み込み直すと自動のタイトルに戻る
- [ ] 大会を読み込んだ直後（参加者の取得中）にタイトル欄へ打ち始め、取得が終わってから欄を離れる → 打った文字が残る（自動のタイトルに置き換わらない）
- [ ] 「コピー」でタイトルがクリップボードに入る（メモ帳などに貼り付けられる）
- [ ] 「追加」でチャンネル名・URL を入れて保存 → 一覧に増え、配信先として選ばれる（下の「配信先 URL」も変わる）。片方が空だと保存できず「両方を入力してください」が出る
- [ ] 選択中のチャンネルを「編集」→ 名前・URL を変えて保存 → 配信先が新しい URL になる。「編集」→「削除」→ 確認で「キャンセル」なら残り、「削除」なら消えて配信先が空になる。チャンネルを選んでいない（URL を直接入力した）ときは「編集」が押せない
- [ ] 「配信先 URL」に直接 URL を打つと配信先になる（コンボは「選択しない」になる）。再起動しても一覧と配信先が残る
- [ ] 団体アイコン / サムネの「画像を選択」→ プレビューが出て、`layout/stream_org_{icon,thumbnail}.png` が長辺 512 / 1920 以下の PNG になる（スマホで撮った .jpg も読める）。画像でないファイルを選ぶと「画像を読み込めませんでした…」、20MB を超えるファイルは送らずに「画像が大きすぎます」が出る
- [ ] 「登録した配信団体の素材を削除」→ 確認で削除すると両方「未登録」になり、背景が「配信団体サムネイル」だったら「大会バナー」に戻る（何も登録していないときはボタンが押せない）
- [ ] 背景とスタイルのラジオが独立して選べる（スタイルを変えても背景の選択が外れない）。オプションを変えて再起動すると選択が残る
- [ ] 「配信サムネイルを生成」→「サムネイルを生成しています…」とボタンの無効化 → 終わるとプレビューと「保存しました: out/stream/thumbnail_...jpg」。生成中も UI が固まらない（オフラインでも保存済み / 既定のバナーで生成される）。団体サムネ未登録で「配信団体サムネイル」を選んで生成するとエラーの文言が出る
- [ ] **デスクトップで**「サムネイルをクリップボードにコピー」→ クリップボードに画像が入り、Discord などへ貼り付けられる（サムネを生成するまではボタンが押せない。Qt 版の「未生成ならコピーで生成してからコピー」は無くなった）
- [ ] ブラウザで `http://127.0.0.1:5107/web/stream` を開いても同じ操作ができ、デスクトップの表示に反映される（チャンネル一覧とオプションは設定なので、もう一方は開き直したときに追いつく）。この PC のブラウザでは画像コピーのボタンが出る
- [ ] LAN の別の PC から（トークン付きの URL で）開くと、画像コピーの代わりに「画像を開く / 保存」が出て、押すと新しいタブで画像が開く。トークン無しで書き込むと「アクセストークンが必要です」が 1 回だけ出る
- [ ] ヘッドレス（`python main.py --headless`）で大会を読み込むと `out/stream/title.txt` にタイトルが出る。ブラウザで `/web/stream` を開くとチャンネル・素材・サムネ生成も操作できる

## 外部制御 API（`/api/v1/`・実装時に確認）

> 仕様: [design/external-control-api.md](design/external-control-api.md)。自動テストは作らず本節を手動でなぞる。
> `python main.py` 起動後、curl 等で叩いて UI / `out/` / OBS / WS で反映を確認する。

### リグレッション（既存を壊していないこと・最優先）

- [ ] 既存 `/score`（POST）・`/scoreboard1-team1-scoreup` 等の旧ルートが従来通り動く
- [ ] Web UI（`/scoreboard`・`/team`・`/web`）が表示され、双方向同期する
- [ ] OBS ブラウザソース／`out/` 出力が従来通り更新される
- [ ] デスクトップ UI・グローバルホットキーの操作が従来通り効く
- [ ] Socket.IO の `program_state` / `program_state_update` 購読が従来通り届く

### 新 API の動作

- [ ] `GET /api/v1/state` がフル状態を `{"ok":true,"data":...}` で返す
- [ ] `GET /api/v1/health` が `activeBoard` / `currentGame` / `revision` 等を返す
- [ ] `POST /api/v1/scoreboards/1/teams/1/score:adjust {"delta":1}` でスコア +1 され、OBS/Web に反映
- [ ] 同操作を `Idempotency-Key` 付きで再送しても二重加算しない
- [ ] `POST /api/v1/scoreboards/1:clear`（confirm 無し）が 409 CONFIRMATION_REQUIRED で**状態を変えない**
- [ ] `confirm:true` 付きで clear が実行される
- [ ] 重い操作（`POST /api/v1/tournament` 等）が 202 で返り、完了が WS で観測でき、実行中の同種要求が 409
- [ ] 範囲外 `{n}`（0 や 4）が 400 INVALID_ARGUMENT になる
- [ ] board3 に board1/2 用操作（score:adjust 等）を投げると明示拒否される
- [ ] 書き込み操作が操作ログ（INFO）に出る／読み取りは出ない
- [ ] OBS 機・操作端末が**別 PC**でも LAN 内から `/api/v1/...` に到達できる（運用想定の確認）
