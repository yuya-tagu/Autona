# Autona ドキュメント基盤

このディレクトリは、**既に実運用されている Autona** を壊さずに今後の変更
（Companion / Stream Deck 連携、外部制御 API、OBS 連携拡張など）を安全に進める
ための運用・設計ドキュメント置き場です。

## このディレクトリの目的

- 既存の**仕様・運用制約・設計判断**をリポジトリ内に蓄積する
- **調査・設計と実装を分担しても引き継げる**情報源にする
- 「動いているものを壊さない」ための、変更前チェックの拠り所にする

## ディレクトリ構成

| ディレクトリ | 役割 |
|-------------|------|
| [`product/`](product/) | 既存機能・画面・ユーザー操作・利用シナリオ・業務フロー |
| [`architecture/`](architecture/) | 現在のアーキテクチャ・主要モジュール・責務分離・データ/状態の流れ・外部連携 |
| [`operations/`](operations/) | 実運用手順・配信時の起動順・障害対応・復旧手順・壊してはいけない操作 |
| [`decisions/`](decisions/) | ADR 形式の意思決定ログ（なぜその設計/制約にしたか） |
| [`changes/`](changes/) | 複数 PR にまたがる作業の短命チェックリスト（完了したら削除）と、テスト戦略の手引き |
| [`development/`](development/) | 開発者向け（地雷回避ルール・リファクタ候補・手動テスト手順） |

## 運用フロー

- 記録は **PR 説明文とコミット**に一本化する。履歴は git に任せ、文書には現在形だけを書く
- 文書を更新するのは、**外部契約**（API・保存データ・layout の契約）か**不変条件**が変わったときだけ。コードが正本のものは文書に写さない
- 意思決定（なぜその設計/制約にしたか・採用しなかった案・見直し条件）は `decisions/ADR-NNN.md` に残す
- 複数 PR にまたがる作業に限り、`changes/<topic>.md` に 50 行以内のチェックリストを置いてよい。完了時に削除する
- 実装後は `product/` `architecture/` `operations/` を実態へ追従させる。仕様が変わったら `architecture/Design.md`（正本）も更新する

## 他ドキュメントとの関係

このディレクトリは**運用・変更管理の視点**を担う。実装の正本は別にある。

| ドキュメント | 役割 | 正本 / 参照 |
|-------------|------|------------|
| [`../CLAUDE.md`](../CLAUDE.md) | 開発原則・Git 方針の要点・アーキ概要・参照マップ（詳細索引は [`../.claude/README.md`](../.claude/README.md)） | 開発運用の正本 |
| [`../docs/architecture/Design.md`](architecture/Design.md) | UI 実装方式・データモデル・画面仕様・デザインシステム・ホットキー | **実装仕様の正本** |
| [`product/features.md`](product/features.md) | 機能一覧・運用制約・リグレッション禁止リスト | 機能一覧の正本 |
| [`../ROADMAP.md`](product/ROADMAP.md) | 将来機能の提案（PdM） | 参考 |
| [`positioning.md`](positioning.md) | タグライン・ポジショニング・差別化・メッセージング規則 | **対外メッセージングの正本** |
| `docs/`（本ディレクトリ） | 運用制約・設計判断・短命チェックリスト | 運用・変更管理の視点 |

矛盾があった場合の優先順位: **コードの実態 > `docs/architecture/Design.md` > `CLAUDE.md` > その他 Markdown**。
`docs/` 配下に書く内容が実装仕様に踏み込む場合は、Design.md を正本として参照し、
ここには「運用・変更時に注意すべき点」を書く。

> **ステージストライク機能は削除済み**（旧 `StageStrikePage` / `/stage-strike-app` / `ruleset`・`stage_strike` 状態）。
> `docs/` 配下では現行ビルドに存在しない前提で記述する。Start.gg parser には互換データとして
> `stage_strike` / `ruleset` を読む処理が残るが、操作 UI / 外部制御 API の対象ではない。

## 記入ルール

- **確認できない既存仕様は推測で書かず `TBD` とする。** 確認方法（読むべきファイル/手順）を併記する
- 既存アプリケーションコードの変更はこのドキュメント作業では行わない
- 相対日付は絶対日付に変換して書く（例: 「来週」→ `2026-06-21`）
- 既存ドキュメント（`CLAUDE.md`・`.claude/`）と重複させず、相互リンクで参照する
